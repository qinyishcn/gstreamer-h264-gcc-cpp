H.265 RTP 丢包：错误掩盖与恢复机制实测

测试日期：2026-10-08 · C++17 / GStreamer 1.28.2 / x265 / FFmpeg HEVC

完成 252 次试验。PSNR 对每个源时间戳计分，包含保持帧和黑帧。这些是 GStreamer 实际编码、RTP 分包、丢包、解包与解码的结果；确定性回放没有引入网络抖动、RTT 或迟到截止时间。UDP 实时示例另行验证，不能将本表解释成真实链路的延迟性能。

实测结论

2% 独立丢包下，多 slice + 短 GOP + 上一帧保持改善了本次两段素材的 PSNR，但绝对画质仍明显受损。保持帧主要解决缺新帧时的黑屏，不能修复已解码出来的马赛克。

序列普通容错 + 保持 PSNR-Y多 slice + 短 GOP + 保持 PSNR-Y增益
FourPeople12.81 dB16.27 dB+3.46 dB
KristenAndSara11.73 dB15.33 dB+3.59 dB

无丢包时 FourPeople 的组合方案比长 GOP 普通方案低约 1.87 dB；KristenAndSara 则基本持平。短序列 ABR 实发码率不同，后文同时列出代价，避免过度归因。

测试口径与复现边界

两段 Xiph 公共领域 720p 序列 FourPeople、KristenAndSara，各取官方 WebM 解码后前 300 帧，60 fps（5 秒）。参考是固定的 WebM 解码画面，已经带有原始 VP8/VP9 压缩损伤；结果不等于相对无损原始 Y4M 的 PSNR。没有将原本的 WebM 质量损伤重复计入本次 HEVC 失真。每种设置独立编码一次并复用包序列，目标视频码率 3000 kbit/s、ultrafast、zerolatency、无 B 帧、closed GOP、scenecut=0。长 GOP=120（2 秒），短 GOP=30（0.5 秒）；slices=1 或 4。IDR 重复 VPS/SPS/PPS。丢包为每 RTP 包独立 Bernoulli 事件，种子 17/42/2026；VPS/SPS/PPS 与首个 IDR 同样可能丢失。同编码流的严格/容错/保持策略使用完全相同的丢包掩码；不同 slice/GOP 改变包数，只有同种子同分布，不能声称丢的是相同画面位置。IPv4 IP MTU=1500，RTP 包最大 1472 bytes（已含 RTP 头），再加 UDP 8 与 IPv4 20 bytes。末包不填充到 1500。纯码流丢包回放将 surviving RTP 包的源时间戳送入 depayloader，显式保留序号间隙与 DISCONT；不用墙钟抖动缓冲，以免未建模的迟到丢包混入概率。

机制含义

配置解码与显示策略
strict_black单 slice、GOP120；output-corrupt=false，discard-corrupted-frames=true；没有输出则黑帧。严格对照，不是 GStreamer 默认行为。
native_black单 slice、GOP120；允许解码器输出受损图像，缺帧时黑帧。avdec_h265 默认本就允许部分受损输出，不能把开关称为新增掩盖算法。
native_hold同一容错解码流；没有新帧则重复上一已输出帧。保住画面，但损坏参考帧仍会传播误差。
slices_hold4 个独立 slice、GOP120，容错输出与上一帧保持。减少单个 NAL 受损的覆盖范围，但丢失首 slice 或参数集仍可能影响整帧。
short_gop_hold单 slice、GOP30，容错输出与保持。周期 IDR 清理参考误差；IDR 自身也可能受损，不能保证 0.5 秒内恢复。
slices_short_gop_hold4 slices、GOP30，容错输出与保持。结合空间分区和周期恢复，码率、分包开销及无丢包质量均需同时比较。

所有模式 max-errors=-1。掩盖不是从无到有恢复丢失的编码信息；这里没有修改 HEVC 解码器的运动补偿算法，也没有实现 FEC、ARQ、RTX 或 RTCP PLI 反馈。

指标解释与限制

PSNR-Y=10log10(255²/MSE-Y)，先汇总该试验所有源时间戳的 SSE 再除以像素数；PSNR-YUV 对全部 I420 样本汇总 SSE（按样本数 Y:U:V=4:1:1），不是三个 dB 数的加权平均。表格跨种子取试验 PSNR 的均值与样本标准差。仅三个种子，不代表稳定的总体置信区间。丢帧处只使用已输出的上一帧，首帧之前用 Y=16,U=V=128 黑帧；不插入未来帧。受损解码可能产生重复 PTS 或时间范围外的 PTS：每个源槽只接受第一次输出，范围外输出丢弃并计数，不为提高分数重排帧。CORRUPTED 标志不保证标出全部马赛克；没有标志不代表画面正确。最长无新帧指标是连续缺输出槽长度；不等同于画面内容未变化时长，也不等同于带重排序/网络延迟的实时恢复耗时。两段素材都是低至中运动的人物场景，5 秒时长且只测独立丢包；不能外推到高运动、长时间、突发丢包或硬件解码器。固定目标码率的短序列 ABR 可能偏离目标，表中给出实际 RTP/IP 等效码率；不同编码设置应同时查看无丢包质量与实发码率，不能将收益全部归因于解码掩盖。

实际使用建议

容错解码 + 上一帧保持可减少因缺帧产生的黑屏；短 GOP 能增加恢复机会，但会有编码效率和 IDR 开销。多 slice 的收益必须以本表衡量，不能预设它必然更好。建议针对业务运动场景重新运行测试，必要时再加入带反馈的 IDR 请求或 FEC/重传。完全未收到可解码启动帧时没有可保持的画面，这种情况不能承诺不黑屏。

验证证据

三个自动化测试通过（核心计分/时间轴、实际编码解码、UDP 收发与固定节奏保持）。矩阵核查覆盖 252 个试验、84 个汇总分组、75,600 个源帧计分槽。另用 FFmpeg psnr 独立核对组合方案 2%、seed42 的 Y4M 输出：FourPeople PSNR-Y=16.738555 dB、PSNR-YUV=18.467864 dB；KristenAndSara PSNR-Y=15.384173 dB、PSNR-YUV=17.041005 dB，与 C++ 对应试验一致。这些单种子结果与上表三种子均值不同。
